# Decisions

## 2026-10-12 — Deeper model-directed agent and observable product

User requests principal-level AI engineering depth and more substantive layers. Implement bounded model-selected observations and document pixels, public hypothesis memory, correction, persistent checkpoints/receipts and a local evidence/review workbench. Source/runtime/client/pricing fingerprints bind recovery and review. Keep old diagnostic/single-call paths for comparison. Distinguish actual SDK HTTP protocol checks and real browser capture from live model/VLM performance. Unknown streams retain admission; complete receipts can be reused without another generation. Native pages are implemented now; React/Temporal/PostgreSQL remain gated proposals.

## 2026-10-12 — Enterprise workflow agent selected

User selects enterprise workflow agent for the second flagship. Choose an original short-shipment lane that complements VerifyOps with state-changing actions, intended multimodal browser interaction and uncertain-outcome recovery. Existing personal repositories are excluded. Broader portfolio/AI-engineering roles remain in scope.

## 2026-10-12 — Environment and independent final state before capability claims

Implement original local world, strict proposals, exact digest approval and a controlled executor; distinguish known diagnostic success from live AI. Current LangGraph collects four observations and proposes once; dynamic autonomy is future work. Private simulation must never mutate the original world.

## 2026-10-12 — Local kernel storage versus release lifecycle

SQLite is only the initial fixture/journal backend. Proposed release uses PostgreSQL and Temporal, with one recovery authority and broker-enforced action identity. No scalable/distributed queue or atomicity across external services claimed. Unknown receipts block retry until explicitly reconciled; changed source invalidates approval; partial execution is retained.

## 2026-10-12 — Bounded live connector early

Official AsyncAnthropic; no urllib; input/time/output/estimated-cost admission, zero generation retries and persisted unknown receipts. One request per fresh run. Live generation awaits private configuration and funding; full HTTP compatibility/provider edge cases and autonomous browser loop remain next work. Do not defer live evaluation behind months of orchestration.

## October 14 — Durable queue before container replicas

Persist API requests and separate worker ownership before adding Kubernetes replicas. PostgreSQL uses `FOR UPDATE SKIP LOCKED`; SQLite remains the offline adapter. Expired owners cannot publish and interrupted work is never automatically replayed. This makes API restarts independent of worker execution while retaining conservative paid-call/receipt semantics.

Choose same-node RWO storage while the authored fixture business worlds, action receipts and graph checkpoints remain SQLite files. A distributed queue does not make these files distributed-safe; multi-node scale needs their database/object-store migration. Kind validates the actual API restart/browser/review/execution journey, while policy enforcement and cloud availability remain separate gates. Shared Basic/Bearer operator access is an interim integration boundary, not individual OIDC authorization.


## October14 — Executable public sandbox

Use request-bounded original fixtures and signed browser envelopes for Vercel interactive actions. Retain full private durable workers separately. This supports real verification/execution in public without claiming persistent effects or immutable global review. Browser session history and explicit replay/fork limitations are accepted tradeoffs; a shared ephemeral SQLite queue is not used for the new endpoints. [Details](14-INTERACTIVE-PUBLIC-DEMO.md).
